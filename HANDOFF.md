## 0. One-paragraph summary

StructLLM fine-tunes an open model (Qwen3-8B, LoRA) to drive StructSub (the user's
platform for building, editing and simulating molecules, MOFs, zeolites and crystals)
through its MCP server. Training data is generated by a teacher model (Claude Haiku 5.5,
mostly) answering synthetic user requests against a live StructSub dev server, filtered by
structural checks and a number-grounding check. **Data and code are ready. The GPU
training run has not been started.** The user will run it on their HPC cluster. After
that: replay the held-out conversations through the tuned model, then a cheap round 2 of
data for the tools added since.

## 4. What was built in StructLLM (all uncommitted, repo has one commit)

The repo's only commit is "first commit"; essentially everything is untracked. **Nothing
has been committed by the assistant.** Suggest the user commit soon.

- `structllm/train.py`: LoRA training with **evaluation inside the loop**: eval loss on all
  held-out turns plus a fixed sample of generated turns scored by `behaviour.py` (decision,
  tool names, schema-valid arguments, exact arguments, grounded numbers, no invented tools).
  Writes `metrics.jsonl`; checkpoints `last/` (with optimiser state) and `best/` (highest
  behaviour score, ties by eval loss); `--patience`, `--eval-every`, `--resume`.
  The loss is computed only over the target turn (`logits_to_keep`), so memory scales with
  the prompt, not with the 150k vocabulary. Verified equal to the library loss (2e-6).
  Verified end to end on CPU with a tiny random Qwen3 (train, evaluate, checkpoint, best,
  resume). **Never run on a GPU.**
- `structllm/behaviour.py`: per-turn behavioural scoring (tests: `tests/test_behaviour.py`).
- `structllm/datagen/grounding.py`: rejects any reply stating a number that no tool result,
  tool argument, user message or tool definition supports (allows differences/sums,
  percent vs fraction, scientific notation; skips turns with no tool call).
- `structllm/datagen/export.py`: `export-sft` adds **prefix salvage** (the passing opening
  turns of rejected conversations) and the grounding filter; `assemble-sft` joins exports,
  normalises the system prompt to the current one, keeps train scenarios out of eval.
- `structllm/orchestrator.py` `SYSTEM_PROMPT`: added "Act, do not discuss" rules and tool-choice
  guidance (see section 6).
- `structllm/datagen/scenarios.py`: static setup check now supplies a placeholder revision.
- `hpc/submit.slurm`: one script that builds the venv, checks the GPU, runs `--prepare-only`,
  trains with in-loop evaluation, resumes automatically. Defaults: `MAX_LENGTH=32768`,
  16 h, 1 GPU, 4 CPUs, 48 GB. `README.md`: full run instructions and recipes.
- Tests: `tests/` has 83 passing (`.venv/bin/python -m pytest -q tests`).

## 6. Policy decisions baked into the system prompt (and why)

All are in `SYSTEM_PROMPT` (training data is normalised to the current text at assembly):

- Act, do not discuss; use sensible defaults and say which; ask only when a missing value
  would make the result meaningless. (User wants execution, not discussion.)
- Hexagonal layers (graphene, h-BN, MoS2) stack AB unless told otherwise. (`stack_layers`
  defaults to AA, so the model must pass `mode: AB`.)
- Build a molecule from a common name by writing its SMILES (or `lookup_name`) and calling
  `build_structure`; `preview_fragment`/`preview_guest` create no structure (Haiku kept
  using them).
- Attach a group with no stated position: act on the first suitable hydrogen, say which.
- To replace a linker/node/fragment in an existing structure: `find_sites` then
  `substitute`; `build_framework` makes a new framework, it is not an edit.
- Measured powder patterns are identified by the id `pxrd_get_pattern` lists, not the file name.

## 10. Findings about StructSub worth remembering

- **Probe tools for free**: `scratch/explore/probe.py` (`P.call(tool, params, ...)`) calls the dev
  server directly with `prepare_call` (see `t_*.py` there for working chains). Use it to validate
  scenario specs before paying a teacher.
- `build_framework` chain: `search_sbus` (ids inline) then `open_building_unit` (`sbu`, `metal`,
  `keep`, `join`) then `get_building_unit` for node and linker, `match_frameworks`, `build_framework`.
  `list_sbu_library` returns its ids in an **artifact** the model cannot read; avoid it.
- `substitute`: `suggest_names` (MOF-5 id 365) then `open_named_framework`, `find_sites`
  (`selector: sbu, kind: linker`), `substitute` (`fragment: {library: biphenylene}`). Fragment
  library names: `list_fragments`.
- PXRD: `pxrd_import_pattern` (no `dataset` field on import; it means an existing pattern). The
  returned `experimental.id` is what `pxrd_select_pattern` and `pxrd_compare` take as `dataset`.
  `pxrd_get_pattern` lists `measurements` with ids. `pxrd_refine_cell` `method` is `structure` or
  `le_bail`. `pxrd_fit_stacking` runs on a single layer with a pattern attached.
- `build_structure crystal` takes a space-group string, **not names** (`graphene` is invalid:
  `P6/mmm a=2.46 c=15; C 1/3 2/3 0`). Setup steps after the first get the previous revision injected
  automatically.
- Zeolites: `LTA; Si/Al 1; cation Na` needs `supercell 2 2 2` (Loewenstein); faujasite cannot go
  below Si/Al 1.5 so zeolite X maps to 1.5; `CHA; 3 wt% Cu2+` builds but 2 and 4 wt% fail (charge
  balance); 14 of 60 frameworks are named for aluminophosphates but build as silicon frameworks;
  only 60 of the roughly 250 IZA frameworks exist (AEI, MTW, MEL, EMT, HEU, DDR absent).
- `lookup_name` fails on zeolite aliases (ZSM-5, zeolite X/Y, faujasite, beta, SSZ-13) and returns
  **confident wrong matches** via PubChem (NaY gave an organic acid, 13X gave phloroglucinol).
- Formulas that need a choice: TiO2, BaTiO3, ZnO, CsCl, CdTe, LiFePO4 (`structure_type_candidates`).
- The docs say a spinel `crystal` without `origin` is refused; the server built it. Possible
  discrepancy; unconfirmed.
- Tool results can be huge (pattern arrays); the orchestrator bounds them for the model.

## 12. Gotchas

- **System volume fills up** (`df -h /`, often 1 to 3 GB free). When it hits 0 every Bash call fails
  with ENOSPC on `/private/tmp/claude-...`. Cause seen: large CPU runs swapping. Do not run big CPU
  jobs; ask the user to free space if it recurs.
- macOS BSD `sed -i` needs `-i ''`; use python for in-place edits. `timeout` is not installed.
- Use the Read/Edit/Write tools for files; for long waits start a background command and wait for
  its notification (a bare `sleep` is blocked).
- `generate-requests` never overwrites its output; pick a new filename. Slots used only in `setup`
  are hidden from the request writer. A turn's `tools` mean "any one of these succeeded".
- The IDE shows lint noise (line length, an unused import in `orchestrator.py`); it is pre-existing
  and ignored.
- `stuctllm/` (typo) is an empty stray directory in the StructLLM repo.
